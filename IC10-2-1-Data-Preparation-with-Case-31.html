Case 31 Employees Federal Credit Union

Author

Overview

In this assignment, I prepare survey data for analysis using R and Quarto. The data come from Case 31, Employees Federal Credit Union. I read an SPSS data file, inspect it, document the survey variables, clean coding problems, reverse-code selected items, and decide whether two multi-item measures can be combined into indexes.

The goal is a transparent, reproducible workflow that another analyst can follow. I used the Case 31 description and questionnaire (Case Exhibits 31.1 and 31.2) throughout to check what each variable means and how it is coded.

Learning outcomes

After completing this assignment, I should be able to:

  1. Import an SPSS file into R with haven::read_sav().
  2. Inspect variable names, labels, value labels, data types, and missing values.
  3. Build a basic data dictionary from SPSS metadata.
  4. Distinguish raw questionnaire variables from precomputed variables.
  5. Treat special response codes (such as “No Opinion”) as missing values.
  6. Reverse-code items so that larger values have a consistent meaning, and recognize when reverse coding does not make sense.
  7. Use reliability and a one-factor analysis as quick evidence for whether a multi-item index is warranted.
  8. Create an index only when the evidence and the item meaning support it.
  9. Add, edit, and remove variable labels and value labels with the labelled package, using the case coding instructions.
  10. Render a Quarto document to HTML and publish it on GitHub Pages.

  4. What is the difference between a variable label and a value label?

Your answer:

  1. The data has 128 rows (one per respondent) and 34 columns.
  2. The variables are q3 to q27, q30 to q34, q37, q38, OverallEmployeePerformace, and employeeperformance.

2 Create a data dictionary

SPSS files store metadata that is not visible in the data frame itself. haven keeps it as attributes. The chunk below builds a compact dictionary with each variable’s label, class, number of distinct values, and value labels.

data_dictionary <- tibble(
  variable = names(data_raw),
  variable_label = map_chr(data_raw, \(x) attr(x, "label") %||% ""),
  class = map_chr(data_raw, \(x) class(x)[1]),
  n_distinct = map_int(data_raw, n_distinct),
  value_labels = map_chr(
    data_raw,
    \(x) {
      labs <- attr(x, "labels")
      if (is.null(labs)) "" else str_c(labs, "=", names(labs), collapse = "; ")
    }
  )
)

5.2 Reverse coding

  • List of items to reverse-code:
    • q7, q8, and q37: very high to very low (1 = very high, 5 = very low) and excellent to very poor

For a scale that runs from a minimum to a maximum, the formula is:

\[\text{reversed} = \text{minimum} + \text{maximum} - \text{original}\]

For a scale starting at 1, this equals maximum + 1 - original. From Exhibit 31.2, q7, q8, and q37 run 1 to 5, and q10 runs 1 to 4.

Arithmetic on a labelled variable returns a plain number, so the old labels are not carried over. That is the right behavior, because the old labels would now be wrong (for example, 1 used to mean “Very High”). New variable labels and value labels describe the reversed direction.

6.3 Questions to answer

Your answer:

Employee proficiency (q3 to q6)

  1. The raw alpha is 0.87, which is strong reliability.
  2. Every item contributes. The r.drop values run from 0.66 (q3) to 0.82 (q4), and dropping any single item would lower alpha, not raise it. None of the items correlate weakly or negatively, so no reversing is needed. That fits the wording, since all four are positively worded statements.
  3. Yes. All four items load strongly on one factor (0.72 to 0.92), and the factor explains about 63% of the variance. q4 (“helpful”) has the strongest loading. The RMSEA (0.20) is high, but with only four items, 128 respondents, and a two-degree-of-freedom model, that fit index is not very stable, and the loadings and residuals (RMSR = 0.05) look good.
  4. Yes. Courteous, helpful, professional, and available are all ways members judge the employees they deal with, which matches the case objective of measuring member attitudes about employee proficiency.
  5. I recommend creating the employee proficiency index. The statistics and the meaning of the items both support it.

Operational effectiveness (q30 to q34)

  1. The raw alpha is 0.54, which is low.
  2. The items do not hang together well. The r.drop values are weak (0.22 to 0.48), with q33 (0.22) and q34 (0.22) the lowest. None are negative, and all five statements are positively worded, so the weak correlations are not a reverse-coding problem.
  3. No. Only q32 (“CU is prompt”) loads strongly (0.79). The others load between 0.30 and 0.40, and the single factor explains only about 23% of the variance.
  4. Not really. The items cover different things: loan rates compared to other lenders (q30), confidentiality (q31), speed of processing (q32), whether services meet members’ needs (q33), and how easy the loan application is (q34). A member could feel very differently about rates than about privacy, so it makes sense that they don’t form one dimension.
  5. I do not recommend creating an operational effectiveness index. The low reliability and weak loadings, plus the fact that the items measure separate aspects of the credit union, suggest they should be analyzed one at a time.

6.4 Create indexes only when justified

Based on the evaluation above, I only created the employee proficiency index. Each respondent’s index is the mean of q3 to q6, so it stays on the original 1 to 5 agreement scale. rowMeans() returns NaN for a respondent with no valid answers, so the code converts NaN to NA.
